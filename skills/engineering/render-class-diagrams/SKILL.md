# 绘制可移植类图

## 内置规范与资源

先读 [类图绘制规范](references/class-diagram-guidelines.md)。用户当次要求优先于默认规范。

- 需要写法示例时读取 [双图示例](assets/example.md)。
- 调整视觉、方法分类或交互时读取 [展示模板](assets/viewer.html)。
- 调整对齐时读取 [布局器](assets/class-diagram-layout.js)，确认 TB、层级有间隔及竖直端点的适用条件。

本技能自带模板、Mermaid.js 12.3.0、布局脚本和许可证，不读取特定项目的 `design/`、配置或依赖缓存。运行生成器只需 Python 3.9+ 标准库，查看 HTML 只需现代浏览器，无需联网、Node.js 或 Maven。核对真实代码所需的源码仍由当前任务提供。

## 绘制与更新

**源码跳转是插件的核心交付。** 基于真实代码生成交互 HTML 时，默认提供类和展示方法的源码入口。

1. 明确主题、源码/依赖版本和图的范围。默认创建类和展示方法的源码跳转入口，无需用户额外提出；读取规范中的“IDEA 插件源码跳转”，核对真实声明与准确方法签名后编写符号映射。目标仓库另有代码定位要求时遵循该仓库规则。
2. 在用户指定目录编写 `<topic>.md`。各图用标题分隔，采用 `classDiagram` 和 `direction TB`；写出类型标记、核心方法、职责注释、原生节点样式及每条关系的文字。说明辅助接口等简化范围。
3. 类/接口沿用规范底色，方法按语义分类。未知方法需要在生成页面的 `methodKinds` 中补充或调整映射，并验证颜色；不能把名称相同当成语义相同。重复生成会恢复模板映射，需保留当前任务要求的修改。
4. 用技能目录内脚本生成页面。下面的 `<skill-directory>` 指当前 `SKILL.md` 所在目录，不是目标项目路径：

   ```bash
   python3 <skill-directory>/scripts/render_diagrams.py /path/to/topic.md \
     --source-map /path/to/symbols.json --require-source-links
   # 输出到其他目录：追加 --output /path/to/output/topic.html
   # 明确更新已有产物：追加 --overwrite
   ```

   默认命令同时传入 `--source-map` 与 `--require-source-links`，覆盖每个类及展示方法。映射使用核实的类全限定名与准确方法签名，核对目标项目实际导入的依赖及版本。更新已有图时同步更新映射并重新检查覆盖。缺少源码或准确签名时，先利用当前项目可用的源码、同版本依赖或 IDE 补齐；仍无法确定则报告具体缺项，不编造映射或静默交付无链接页面。用户明确要求纯图时可省略映射；概念示例没有真实源码时说明无法提供真实跳转。源码副本只用于用户明确选择的文件跳转模式。

   运行资源包括运行库、布局器、许可证和 Markdown 快照。生成器严格保留类图源码，缺少关系标签时报错，不推测类型语义。
5. 移交时同时提供 HTML 和模块目录；生成页面不再依赖技能安装位置或源 Markdown 的原位置。只需发布此技能文件夹即可分发技能，无需原始项目；远程推送仅在用户明确要求时执行。

## 文件布局

HTML 统一放在交付目录顶层。将 Markdown、符号映射（如适用）归入 `class-diagrams/`，审计资料按需放进模块内的 `audits/`。运行资源由生成器写入 `class-diagrams/<topic>.assets/`。`--overwrite` 会替换该资源目录并清理上次生成的源码副本，输入和手写文件应保存在资源目录之外。源 Markdown 位于模块目录时，默认在其上一层生成同名 HTML；`--output` 可指定 HTML 路径。迁移时保持模块目录与 HTML 的相对位置。

## 完成条件

- 核对本次每条继承/实现线及类型标记，注明版本、依据和省略范围；不照搬示例的类型或审计结论。
- HTML 的 `diagram-data` 与输入类图逐段一致，资源目录中的 `source.md` 与本次输入一致。
- 浏览器实际渲染所有新图；按规范检查受影响的同层对齐、横平竖直连线、端点、适应整图、导航不跳动、展示模式、缩放和独立 SVG 样式。
- Java 符号映射可用 `scripts/audit_source_map.py` 对照调用方提供的 classpath 和 JDK `javap` 核对声明；它不证明 IDEA 已索引或成功打开。
- 技能模板或打包方式改动时，将技能单独复制到干净目录运行；再把生成产物单独迁移并在不依赖原目录的情况下验证。
- 默认交付包含独立符号映射 JSON，并通过 `--require-source-links` 的覆盖检查；纯图片段或概念示例按上述例外处理。源码导航需分别验证映射覆盖、目标 IDE 解析和真实打开结果；完整检查时报告各图类/方法入口数、成功数、歧义和未找到项。在 Diagram Source Navigator 中用 **Open HTML Diagrams…** 打开本次生成的 HTML，逐图核对可点击入口并实测类和方法跳转。若渲染后没有预期入口，先检查页面是否加载了本次生成的映射。以 IDEA 实际打开的声明为验收依据，分别记录映射覆盖、页面入口和实际跳转结果。
- 返回 Markdown、HTML、符号映射 JSON 和资源目录路径；仅报告实际执行过的验证。用户只要片段或 Markdown 时尊重该交付范围。

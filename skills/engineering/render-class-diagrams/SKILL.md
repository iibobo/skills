# 绘制可移植类图

## 内置规范与资源

先读 [类图绘制规范](references/class-diagram-guidelines.md)。用户当次要求优先于默认规范。

- 需要写法示例时读取 [双图示例](assets/example.md)。
- 调整视觉、方法分类或交互时读取 [展示模板](assets/viewer.html)。
- 调整对齐时读取 [布局器](assets/class-diagram-layout.js)，确认 TB、层级有间隔及竖直端点的适用条件。

本技能自带模板、Mermaid.js 12.3.0、布局脚本和许可证，不读取特定项目的 `design/`、配置或依赖缓存。运行生成器只需 Python 3.9+ 标准库，查看 HTML 只需现代浏览器，无需联网、Node.js 或 Maven。核对真实代码所需的源码仍由当前任务提供。

## 绘制与更新

1. 明确主题、源码/依赖版本和图的范围。核对真实声明后再画继承/实现关系；目标仓库另有代码定位要求时遵循该仓库规则。
2. 在用户指定目录编写 `<topic>.md`。各图用标题分隔，采用 `classDiagram` 和 `direction TB`；写出类型标记、核心方法、职责注释、原生节点样式及每条关系的文字。说明辅助接口等简化范围。
3. 类/接口沿用规范底色，方法按语义分类。未知方法需要在生成页面的 `methodKinds` 中补充或调整映射，并验证颜色；不能把名称相同当成语义相同。重复生成会恢复模板映射，需保留当前任务要求的修改。
4. 用技能目录内脚本生成页面。下面的 `<skill-directory>` 指当前 `SKILL.md` 所在目录，不是目标项目路径：

   ```bash
   python3 <skill-directory>/scripts/render_diagrams.py /path/to/topic.md
   # 输出到其他目录：追加 --output /path/to/output/topic.html
   # 明确更新已有产物：追加 --overwrite
   ```

   如用户需要本地源码跳转，读取规范中的“IDEA 插件源码跳转”，提供 `--source-map`；使用类全限定名与准确方法签名，完整覆盖时追加 `--require-source-links`。核对目标项目实际导入的依赖及版本；源码副本只用于用户明确选择的文件跳转模式。

   默认输出同名 HTML 及 `<topic>.assets/`，内含运行库、布局器、许可证和 Markdown 快照。生成器严格保留类图源码，缺少关系标签时报错，不推测类型语义。
5. 移交时同时提供 HTML 和相邻资源目录；生成页面不再依赖技能安装位置或源 Markdown 的原位置。只需发布此技能文件夹即可分发技能，无需原始项目；远程推送仅在用户明确要求时执行。

## 完成条件

- 核对本次每条继承/实现线及类型标记，注明版本、依据和省略范围；不照搬示例的类型或审计结论。
- HTML 的 `diagram-data` 与输入类图逐段一致，资源目录中的 `source.md` 与本次输入一致。
- 浏览器实际渲染所有新图；按规范检查受影响的同层对齐、横平竖直连线、端点、适应整图、导航不跳动、展示模式、缩放和独立 SVG 样式。
- Java 符号映射可用 `scripts/audit_source_map.py` 对照调用方提供的 classpath 和 JDK `javap` 核对声明；它不证明 IDEA 已索引或成功打开。
- 技能模板或打包方式改动时，将技能单独复制到干净目录运行；再把生成产物单独迁移并在不依赖原目录的情况下验证。
- 源码导航需分别验证映射覆盖、目标 IDE 解析和真实打开结果；完整检查时报告各图类/方法入口数、成功数、歧义和未找到项。通过插件页面执行检查时保留结果报告，不能把 HTTP accepted 或候选列表记为 opened。
- 返回 Markdown、HTML 和资源目录路径；仅报告实际执行过的验证。用户只要片段或 Markdown 时尊重该交付范围。
